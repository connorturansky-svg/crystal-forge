## Contract and layout

- The hamburger + “Models (N)” button is always available in the viewport, with active model name and New model nearby. Default collapsed on full load; state is transient, not saved in project, undo, vault, or revision. Keep drawer open after switching tiles. Reset transient search/open state on project switch; no cross-project editor. Preserve current project name in header and accessible Project : Model label.
- Move the **existing** rail into the centre viewer; no duplicate tab store, no full-width bottom row. Drawer rises over bottom ~33% of actual viewport, not 33vh or page width. Use centre-relative sizing, min-height:0, min-width:0, max-block-size and scrollable grid body; header stays accessible at short heights; permit one-column layout and safe extra space when zoom makes one-third impractical. Do not trap keyboard focus or block sidebars, Layers, camera tools, status or invalid-placement feedback. Outside click may leave drawer open (nonmodal); explicit toggle, Escape and close button dismiss it. No animation for reduced motion.
- Tile = real preview at left, readable name at right, active text/border plus status, independent close/info actions. Grid via CSS, not necessarily ARIA grid. New and close actions remain accessible at all widths. No nested button. Reuse previous arrow/Home/End and Alt+arrow reorder + Delete close where appropriate; provide discoverable keyboard alternatives and focus restoration after rerender, filtering or close. Filter visible tiles by name, not stored tab ordering; clear or disable reorder under filter rather than losing unseen IDs. Closing only removes open tab, not saved model, Library source or print job. Show an empty state; New remains available. Long/Unicode names wrap or truncate visually with full accessible name.
- C1: user-editable meaningful name before commit, suggestion from family/preset/import, cancel writes nothing. Existing valid v1 names untouched; validation requires nonblank names, so legacy-invalid inputs need existing migration policy, not silently rewriting archive. Info action: type, project, stable model ID, revision, linked source/pinned revision, created/updated dates, effective profile dependencies, preview state and job status. Existing rename uses editModel, which increments revision and stales jobs even though name is absent from modelFingerprint. Preserve this explicit policy (no silent prepared-job reattachment); linked edits remain rejected. No new schema needed for drawer.

## Preview pipeline: implement once, reuse in drawer and Library

Proposed new module(s) under src/ui/ with explicit relative URLs (Pages now stages src/). Keep rendering adapter separate from pure cache scheduling. No mass move. Data inputs: stable project/snapshot/model identity + exact immutable source/pinned link, generator type/version, modelFingerprint, source asset identity/content, resolved relevant profile/material dependency and renderer version. Key includes source/revision where needed; never trust model ID alone across snapshots or same-named projects. modelFingerprint currently includes editableState (including selection in practice) but excludes source/link: audit rather than assume geometry-only; avoid recompute on camera, drawer, focus, filter and selection-only changes when proven safe.

- Memory-only derived cache, bounded LRU (initial proposal 128 entries, adjustable from evidence); visible scroll tiles + small lookahead via IntersectionObserver rooted at grid scroller, one render at a time, yield between expensive jobs. Images lazy decode; use one shared thumbnail renderer, not 100 WebGL contexts. Cancel queued work when drawer closes, project changes, key changes or filter removes target; drop obsolete async results using generation token/key check. Catch renderer loss, missing source, invalid geometry and decode failures independently. Retry only explicit request or changed input, not tight retry loops.
- Never overwrite the live scene/camera, run full fabrication/Manifold just for every tile, or save a preview by editModel. Generate from saved Crystal editableState + settings, including hidden/placed/rotated/scaled shapes and actual colours, using existing geometry primitives; native previewRecipe plus applyBuildModules, resolved imported source. Distinguish preview from prepared print mesh. Verify geometry ownership: THREE clone shares mesh resources; dispose only owned temporary geometry/material/texture, never live shared resources. Release object URLs, observers, renderer on teardown. Cache image only when rendered successfully; legacy thumbnail may show as explicitly unverified until refreshed, never mark fresh without provenance.
- Display pending/loading, ready, unsupported, missing-source, invalid-source, render-failed states. Retry where meaningful; specific accessible explanation. Image alt empty if adjacent name conveys identity; model info should say preview source/status. Compare real render silhouettes/materials for all seven families and compatible imports, including saved non-active Crystal changes; no generated lookalike thumbnails.
- Do not introduce source/thumbnail storage schema migration or change cloud data. Future persistent derived cache needs its own validated policy.

## Research applied, not additional scope

W3C APG [Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) supports native button with aria-expanded, optional aria-controls, Enter/Space. [Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) requires composite keyboard behavior; a CSS grid of ordinary buttons/list items is simpler for select + close/info actions. [Keyboard practices](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) guide focus management. [MDN Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API) supports a scroll container as observation root and near-viewport rendering. These are design inputs, not proof of conformance. Test keyboard/touch and actual browser.
