## Using the drawer

Choose **Models** at the bottom of the viewport. Search the open entries or select a tile to switch. Press Escape to close the drawer. Alt+arrow reorders the focused tile. **Close** removes its open entry while preserving the saved model. **Info** shows its project, family and source revision. Choose **New model**, pick a starting point and confirm or edit the suggested name.

The tested preview path reconstructs the saved design, including Crystal's stored editable cluster. Missing geometry gives a reason and Retry. Previews show editable design geometry. Use the prepared mesh in Print Centre for fabrication review. The notes below document the original integration checklist.

## Real preview adapter — do not ship synthetic previews
Observed causes of blank tiles: .sms-rail .sms-picture-empty uses font-size:0, inactive Crystal tabs only use model.thumbnail, and thumbnail()/recipeThumbnail() catch failures as null. This explains possible blank placeholders, not a reproduced failure on the owner's actual data. renderTabs also synchronously calls thumbnail(adapter.previewGroup()) for active Crystal with no stored thumbnail. Remove that rendering from tab updates.
- Reuse thumbnail(group), recipeThumbnail and real saved Crystal editableState. Audit Crystal reconstruction and imported SVG/mesh source resolution against actual persisted records first. A default family/preset is never a valid substitute. Strip overlay/helper geometry and preserve colours. Don't mutate/dispose shared live geometry.
- Candidate queue is serial, LRU-bounded and requests visible cards only. At integration use a key containing project/model identity, revision, modelFingerprint, resolved source/link/profile/material dependencies, renderer version. Resolve immutable snapshot at request time; discard result if source changed. Verify stored thumbnail provenance before reuse; regenerate legacy unversioned previews lazily. Return {src: data:image/png;base64,...} or specific failure reason; retry remains possible. Coalesce pending work, dispose owned resources, cap memory by bytes as well as entries; handle lost WebGL context and project switch. No manufacturing worker per tile. Reuse same adapter for Library later, not duplicate renderer.
- Prototype caveats: no genuine thumbnails yet, no app integration, no full accessible model info/creation flow; narrow and zoom interactions still require real browser checks. Candidate drawer retains open state during switching and uses explicit close button; default collapsed each page load. User requested approximately one-third viewport height; allow minimum usable height on small displays.
